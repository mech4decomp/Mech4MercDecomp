    autoconfig_MERCS.exe — GameOS AutoConfig / Driver-Diagnostics Tool (deep-dive)¶

    Reference record; not an oracle target. See the editor-tools overview.

    2. Purpose¶

    This is not a lightweight graphics-settings editor. It is the GameOS "AutoConfig" driver-diagnostics tool (version string 50.06.09.3002, build tag Version 1.1 11/2/2000):

    1. Probes the machine — processor details, PCI card info, DirectX version, audio/video codec install, modem/lobby providers (GetMachine Details, GetProcessorDetails, GetDirectXDetails, GetGameDetails, GetInstallAudioVideoCodecs, GetPCICardInfo).
    2. Runs the GameOS renderer/driver test suite — enumerates D3D devices, display modes, texture formats and caps, render states, gamma calibration, video memory (local/non-local/AGP), AGP miniport mode (viaagp1.sys detection, TURBO/NORMAL), and DirectSound devices — exactly the same driver probes the game's own startup autoconfig runs.
    3. Writes the results — the selected device/options into options.ini (§4), a VideoCard.txt driver report, and the game registry key Software\Microsoft\Microsoft Games\<game> (§5).
    4. Reports bugs — can submit a crash/report to the FASA "Raid" SQL database (DRIVER={SQL Server};SERVER=%s;...;APP=RAID4).

    The tool is the standalone, interactive form of the game's built-in autoconfig — the same GameOS code paths that MW4Mercs' -noautoconfig switch skips.

    3. Layout — code and data ranges¶

    Range Size Content
    0x401000–0x404xxx ~20 KB App shell + the options.ini writer (FUN_00401b70)
    0x405xxx–0x406xxx ~10 KB INI/section writer helpers (0x403a50, 0x404bd0, 0x4065c0, 0x4067d0)
    0x40xxxx–0x44xxxx ~300 KB GameOS core — the same framework as the game EXE: config/CLI (FUN_00413c50 parses /gosconfig, /gosnovideo, /gosnosound), registry (FUN_0041c9b0), renderer state, texture manager, DirectSound mixer, input
    0x45xxxx+ — VideoCard.txt reporter (FUN_00428a30), PCI-card detail (FUN_00441dc0), sound-device details (FUN_004201c0)
    0x457000–0x465D6E — .rdata: the full D3D/DDERR/DIERR/DSERR error-string tables + render-state enums

    4. options.ini — what AutoConfig writes¶

    The writer (FUN_00401b70, thiscall on a config object) emits an INI with three sections and the game's option keys as name=value lines:

    [Graphics Options]
VideoDriverIndex          DetailTexture    MultiTexture    LightMaps
Culturals                 Footsteps        MissionMusic     NoBlend
AntiAlias                 VertexLighting   SimpleLighting   MipBias
ShadowMode                screenwidth      screenheight     bitdepth
FancyWater                MovieTextures    MaxLights        Compositing
EffectLOD                 LoadRadius       AllowDecalTransfer
[Sound Options]
LowEndSound               Radius
[Special Commands]
KillGame

    Plus the font keys fontsmall / fontmedium / fontlarge / fontlarge2 / fontlarge3 and server. Values are read from the config object's fields (+0x240, +0x340, +0x440, ... — per-option), converted to text via a 0x147-typed formatter, and written through the section writer helpers (0x4067d0 / 0x4065c0). screenwidth/screenheight/bitdepth are the display-mode selection; VideoDriverIndex picks the D3D device.

    These keys are the same option names the MW4Mercs option table consumes (the game EXE's option table at 0x0076C918 + -noautoconfig interplay — cross-reference only).

    5. Registry / file side effects¶

    • Software\Microsoft\Microsoft Games\%s (0x45959C, written from FUN_0041c9b0) — the per-game config key; %s is the game/product name.
    • Software\Microsoft\Multimedia\Sound Mapper\ (0x45AD00) + \DirectSound\ Mixer Defaults / Device Presence — sound device selection.
    • Software\Microsoft\Windows Messaging Subsystem (0x45CEA8) and Config Manager\Enum\ (0x61AC0, hardware key DeviceDesc, HardWareKey, DriverDate, videoram from FUN_00441dc0) — PCI/device enumeration.
    • VideoCard.txt (0x45BD04, written by FUN_00428a30) — a driver report (driver file/version/date/size, video memory, renderer caps).
    • Screen.bmp (0x5D088) — screen-capture output (GameOS @Kscreen%04d.%s screenshot naming).

    6. Per-card compatibility flags¶

    .rdata holds the GameOS per-card workaround registry — the same compatibility knobs the game applies for broken drivers:

    SceneRenderer, NoMultitexture, NoAlphaTest, NoStretchTexture, RenderEqualZ, BrokenAlphaTest, ForceSquareTextures, LimitTextureSize, Limit500VidTextures, AllowLowMemoryCard, DisableTextureDeletes, SlowDisplayModeChange, TextureOffset, LowEndCard.

    These are the auto-selected renderer/tuning flags; AutoConfig tests the device and enables the appropriate ones before writing the option set.

    9. Notes¶

    • The tool shares its GameOS core with the game EXE and the other editor tools (identical CLI switches, registry paths, D3D error tables) — it is the best standalone reference for what the game's startup autoconfig does and which options.ini keys the game reads.
    • .data VSize (0x76818) is ~95% BSS — the GameOS renderer/sound/input global state, mirroring the game's own globals; no layout captured here.
    • No .txt2/SafeDisc section (unlike MW4Ed2).
