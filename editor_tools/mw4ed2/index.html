    MW4Ed2.exe — Mission/Level Editor (deep-dive)¶

    Reference record; not an oracle target. Analyzed with Ghidra; the analysis project and dumps are not part of this repository. No source tree, no byte-identity gate.

    2. Purpose¶

    MW4Ed2 is FASA's Mission Editor 2 — a full in-house mission/level editor that embeds the complete game runtime (renderer through blade, object code through gundll, DirectPlay, the ABL scripting VM, localization). It creates and edits the Resource\Missions\*.mw4 mission archives: pick a map (≈ \Games\*.mw4 browser), lay out spawns/units/lights/drop-zones/skies, bind ABL mission scripts and bot AI, and write the archive whose members are the serialized MechWarrior4::MWMission object graph plus per-aspect binary blobs. It is the companion to MapCreator (which builds the maps/mission terrain) — MW4Ed2 builds what runs on top of a map.

    3. Architecture — a game framework with an editor shell¶

    Two layers:

    • MFC editor shell (356 MFC42 imports): dialogs, toolbars, file dialogs, the \Games\*.mw4 map browser and Resource\Missions\*.nfm / Resource\UserMissions\*.nfm scenario dialogs. Thin compared to the framework below.
    • Bundled game framework (the bulk of .text): the same class/property system the MW4Mercs engine uses, driven headlessly:
    • Class registry — FUN_0046a280(size, "Class::Name", base, ...) registers serializable classes by name; FUN_006d3d80(name, ...) is a second registry flavor. Objects are identified in files by their class tag string (Adept::Mission, MechWarrior4::MWMission).
    • Property system — FUN_00469910(index, "Name", type, offset) + FUN_00469c60(list) register reflected, offset-addressed fields per class. This is the serialization contract (§5).
    • Allocator/factory — FUN_00449aa0(size) (calloc-like, returns 0 on failure); FUN_00449ab0(p) free.
    • GameOS framework (shared with the other editor tools + the game): file system finder (FUN_0043d7e0 set path / FUN_0043d850 next / FUN_0043d9b0), string table loader, the game console/message color helper (FUN_005a4bf0(0xbb7ff, ...) = blue "loading" text).
    • ABL scripting VM — FUN_005a6270(path, ...) compiles/loads an ABL script; mission and bot behavior is ABL (see §6).
    • Full runtime side-loading — the renderer (blade) and object library (gundll) DLLs are referenced by name, so the editor can actually run/render the level being edited.

    4. The mission file format (Resource\Missions\*.mw4)¶

    Ground truth from the shipped coliseum.mw4 (58,948 B) and the sibling mission archives (0001.mw4, alpine.mw4, avalon01.mw4, ...).

    4.1 Container — #VBD v4 (see include/mw4/vbd.h)¶

    Header (43 bytes + path): #VBD (4) · version 4 (4) · count=63 (4) · dir_off (4) · keys (4) · filetime (8) · flags1=0x1A (4) · flags2=0x1A (4) · reserved (6) · path-len (1) · path (resource\missions\coliseum.mw4, 30 chars). The count=63 is a capacity, not the member count.

    4.2 Directory — multi-group rows¶

    The directory is a sequence of fixed-prefix rows grouped by a shared FILETIME:

    filetime (8)  u32  u32  u32  u16 index  u8 name-len  name[..]

    All rows in a group carry the same filetime; consecutive groups differ (a group = one filetime run, e.g. one save session). Member names observed for coliseum:

    missions\coliseum\coliseum.instance        (index 1)
missions\coliseum\coliseum.data{Element}
missions\coliseum\coliseum.data{GameModel}
missions\coliseum\coliseum.data
missions\coliseum\coliseum.lights
missions\coliseum\coliseumnight.lights
missions\coliseum\DropZones\DropTeam2.contents
missions\coliseum\DropZones\SecondaryLanceStart.contents
missions\coliseum\skies\colsm01_sky\colsm01_sky.erf
missions\coliseum\mission.bounds
missions\coliseum\coliseumgraph.data
missions\coliseum\scripts\Coliseum.abl
missions\coliseum\scripts\Coliseum_SinglePlayer.abl
missions\coliseum\scripts\Coliseum_Campaign.abl
missions\coliseum\scripts\player.abl
... (per-game-type script variants)

    Member semantics: .instance (the serialized mission object, see §4.3), .data{...} aspect sub-blobs, .lights/...night.lights (light lists), DropZones\*.contents (spawn/drop-zone sets), skies\<map>_sky\*.erf (environment resource), mission.bounds (bounds), <name>graph.data (nav/unit graph), scripts\*.abl (mission scripts per game type).

    4.3 First member — the serialized mission object¶

    The first member's content begins directly with the map reference as a NUL-terminated path, followed by binary object data:

    "resource\maps\colsm01.mw4"   \0  <binary mission object serialization...>

    i.e. the mission archive is an object graph whose first field is the backing map. The exact directory → data-offset encoding is not fully resolved (multiple groups, variable-length rows; maps decode cleanly at data_off = prev.data_off + prev.stored_size relative to dir_off, but the mission archives interleave group headers — see the #VBD follow-up note in include/mw4/vbd.h).

    5. The mission class + property table¶

    5.1 Class registration¶

    • Adept::Mission — registered by FUN_00462610 (3,144 B) via FUN_0046a280(0x1E6, "Adept::Mission", base, factory, ...) → class size 0x1E6 (486 bytes). This is the mission environment base class.
    • MechWarrior4::MWMission — registered by FUN_00585f60 via FUN_0046a280(0x420, "MechWarrior4::MWMission", ...) → class size 0x420 (1056 bytes); also constructs the StartMusicStatus and TransMusicStatus helper objects. This is the MW4 concrete mission subclass (the .instance member's top-level type).
    • Mission — registered by FUN_006d3d80("Mission", ...).

    5.2 Adept::Mission property table (the serialized environment)¶

    FUN_00462610 registers 55 reflected properties (index, name, type-code, offset-in-class). Type codes seen: 1=int, 2=float, 0xE=bool, 0x10=color/vector4, 0x231=string/resource.     6. ABL scripting integration¶

    Mission behavior is bound through ABL scripts stored as archive members (scripts\*.abl), one set per game type (Stock_MissionPlay, Campaign, SinglePlayer, ...), plus shared library scripts:

    • content\ablscripts\miscfuncs.abl — loaded by FUN_00586090 (the ABL library bootstrap; blue "loading" console message, then FUN_005a6270(path, ...) — the ABL compile/load entry).
    • Content\ABLScripts\StockScripts\Stock_MissionPlay.abl — referenced by the mission object (FUN_00586a90's cluster) as the default stock mission script.
    • Content\ABLScripts\Bots\UberBot.abl — the default bot AI script, loaded by the bot subsystem (FUN_00616430, FUN_00616f80, FUN_00618d00, FUN_0061b540 — a 4-site bot-script family in the 0x61xxxx region).
    • scriptName (0x00753954) — the per-mission script-name property binding (referenced from the 0x569xxx mission region).

    9. Notes / follow-ups¶

    • #VBD directory encoding: the mission archives' multi-group directory (shared-filetime row runs, 23-byte prefix) does not match the map archives' single-group layout captured in include/mw4/vbd.h. Worth a dedicated decode pass of a mission archive's directory + data-offset rule.
    • Runtime integration: the editor can load blade/gundll and run the real renderer — the deepest value here is the format of the serialized MechWarrior4::MWMission object graph, which the game itself loads from the same Resource\Missions\*.mw4 files (and which MW4Ed2 writes).
    • Scale: 11,388 functions across a ~3.3 MB .text; this doc maps the mission-format surface and framework seams, not every editor dialog.
